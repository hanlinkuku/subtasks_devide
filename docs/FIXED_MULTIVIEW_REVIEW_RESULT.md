# 固定多视角复核：第一轮结果

## 本轮范围与结论

未引入 Agent。新增固定窗口的四视角全程观察、已有交互的局部复核，以及一次固定的分歧补查；修复交互超出运动区间时静默丢弃的问题。

两条轨迹已完整运行，但新的视觉复核尚未证明更准确。本轮保留原自动标注（11 段、7 段），将新观察作为独立报告，不能将新模型建议直接当成修正答案。当前改进是冲突可追溯、证据覆盖更全面，不是已证实边界准确率提高。

## 已实施

1. 导出前检查完整交互区间是否合法、是否完整属于某个运动区间、是否重叠，以及是否存在未处理的 `additional_actions`。失败时保存 `export_audit` 并抛出错误，不覆盖该阶段已有标注。完整属于后续运动区间的交互仍正常输出。
2. 全程观察采用最长 120 帧的窗口，相邻窗口重叠 30 帧，每窗最多均匀采样 16 个时刻，每个时刻包含四视角。观察时不提供原分段，也不预设操作机械臂。窗口覆盖全程不代表稀疏图片捕捉到了所有短动作。
3. 交互复核在原边界前后扩展 8 帧，两端更密集、中间稀疏，输入四视角。原边界是待复核候选，不是人工真值。
4. 对未匹配观察和额外动作进行一次固定补查，每项最多 18 个时刻，输入四视角、左腕原分辨率细节、双臂运动增量。原分辨率细节目前仍按当前数据集固定为左腕，不宣称已消除所有视角偏置。
5. 缓存记录模型、参数、版本、完整 context、原图哈希、实际构造图片和原始返回文本。工作台读取独立复核报告，展示分歧，不自动覆盖精细边界。

## 实际观测

| 轨迹 | 全程观察窗口 | 已有交互局部复核 | 分歧补查 | 仍待复核的观察条目 | 边界存在分歧的交互 |
|---|---:|---:|---:|---:|---:|
| episode_000000 | 7 | 3 | 8 | 8 | 3 |
| episode_000001 | 5 | 2 | 2 | 2 | 2 |

“观察条目”可能来自重叠窗口或同一事件，不等于新增动作数量，也不等于已证实的漏检。补查返回 supported 仍然是模型意见，不能单独判定新动作成立。

多视角局部模型建议如下，均未采用：

| 轨迹 / 交互 | 原自动区间 | 新建议区间 |
|---|---|---|
| 000000 / 1 | 75–90 | 75–80 |
| 000000 / 2 | 149–175 | 154–174 |
| 000000 / 3 | 436–450 | 439–440 |
| 000001 / 1 | 118–152 | 122–123 |
| 000001 / 2 | 205–220 | 207–208 |

这些建议中多次出现结束帧落在屏幕响应附近、把较长保持压缩成短暂交互的情况，与约定的“推进及保持，直到持续撤离”定义存在分歧。模型还给出未经可靠核实的温度与接触描述，未因其 uncertain=false 就采纳。

补查仍把若干接近阶段解释成按压，并把按钮后撤解释为 release，即使提示词已明确区分这些类别。因此，简单添加四视角拼图或再问一次，并没有形成可靠的自动裁决器。

## 保留的证据

- `outputs/automatic/multiview_refined/coverage/`：全程窗口、采样帧和独立观察。
- `outputs/automatic/multiview_refined/evidence/`：每次 context、图片、模型原始文本及解析结果。

图片按现有 Git 规则仅保留在本地，轻量 JSON 可版本管理。现有人工修订和 v2 工作参考未修改。

## 验证与下一步

两条轨迹均从准备数据到多视角报告完整运行；后续重复运行复用缓存。21 项 Python 检查通过，覆盖越界/跨运动区间、额外动作、交互重叠、后续运动区间保留、全程窗口覆盖及原工作台保存逻辑。编辑器连续区间与拆分合并检查通过。

下一轮应在固定流程内分离“可观察事实提取”和“动作类别判定”，例如先输出屏幕状态变化、物体相对运动、推进/撤离证据，再判断是否独立按压；避免让同一次调用同时猜按钮、温度和精确接触。需要对当前分歧逐一核实，而不是按工作参考的帧数调阈值。该下一轮方案尚未实施。
