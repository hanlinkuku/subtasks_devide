# 实验 001：双臂候选来源

状态：候选函数实验验收通过；尚未接入正式流程的自动手臂选择。

## 要检验的依赖

当前候选生成直接读取左臂 XYZ，右臂即使运动也不会产生候选。这是代码层面可构造反例的缺陷，不把当前两条轨迹上的模型争议当成错例。

## 单变量与验收

只改变运动数据来源：相同的运动区间、峰值和撤离规则分别用于左右臂。保持所有阈值、模型、视觉输入与正式输出不变。右臂输出独立保存，不直接送入仍带左臂提示的视觉细化。

1. 当前两条轨迹：左臂候选必须与原候选相同；分别记录右臂运动区间和候选数。
2. 机制反例：仅交换遥测中的左右臂字段。交换后候选帧必须随手臂字段对称迁移。该检查只证明程序不漏读另一臂，不证明真实右臂视觉标注准确。
3. 两条正式结果与冻结基线内容完全相同；不通过则不接入。
4. 输出仍是运动候选，不能以无平移排除静态交互、转动或夹爪动作；不声称已解决通用候选发现。

无已确认的当前轨迹边界错例，因此不改边界，不宣称准确率提升。若成功，推进的是候选层去除单臂输入预设；右臂视觉处理仍是后续单独实验。

## 实测结果

| 检查 | 改动前 | 改动后 |
| --- | --- | --- |
| episode_000000 左臂候选 | 78—90、138—175、432—450 | 相同 |
| episode_000001 左臂候选 | 101—152、211—220 | 相同 |
| 两条轨迹右臂平移候选 | 不读取 | 均为 0 |
| 左右遥测字段交换 | 原接口仍固定左臂，遗漏转移后的运动 | 候选帧逐一转移至右臂 |
| 正式标注与冻结基线 | 基线 | 完整内容不变，变动帧 0 |

这里列的是运动候选，不是正式 press 起止帧。对照位于 `outputs/experiments/001_bilateral_candidates/`。49 项检查通过，含两条轨迹的字段交换检查。第一轮比较检查因 Python tuple 与 JSON list 表示差异失败，统一到 JSON 表示后通过，未改算法阈值。

本轮没有新增模型请求；正式流程复跑使用已有缓存，两条流程加对照导出的进程耗时约 6.9 秒，不作为线上推理性能指标。

采用范围仅为候选函数支持指定左右臂及独立双臂实验入口。默认主流程仍调用左臂，尚不能将“函数可处理右臂”写成“完整流程不再依赖左臂”。下一轮须单独处理视角、提示和输出手臂的一致传递，才能讨论接入自动手臂选择。
