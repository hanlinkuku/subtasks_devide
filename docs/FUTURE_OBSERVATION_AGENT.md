# 未来扩展方向：受约束的观察 Agent

状态：讨论备忘，暂不实施。

当前决定：不引入 Agent，不按本文重构现有流程。当前工作优先在已有两条轨迹上提高子任务完整性、动作语义和起止帧准确性，继续使用 Qwen3-VL-32B。本文不构成开发排期或实现授权。

## 1. 动机

现有流程的运动候选依赖左臂伸出、远端操作、撤回的场景假设；图像输入主要预先固定为左腕序列。候选漏检或重要视角缺失时，后续局部逐帧细化无法弥补未获取的证据。

未来可研究让模型自主选择下一步观察，帧提取和采样由确定性的工具执行。自主权限于证据获取，不包含任意代码执行、修改原始视频、修改采样规则或访问无关数据。

## 2. 已讨论的核心约束

- Agent 选择观察视角、预制采样方式，以及是否调用目标物体属性观察。
- 工具内置三个观察档位：逐帧、中等、离散。它们是输入图片的采样方式，不是最终子任务的划分规则。
- 工具保留原始帧号、视角名称和时间顺序，不让模型自行编造采样帧。
- 模型维持当前动作假设，根据新证据更新判断，最终输出约定的子任务 JSON。
- 观察物体属性只描述可见内容，不把遮挡、模糊或推测补成确定属性。

## 3. 工具接口草案（未定稿）

### observe_sequence

输入：轨迹 ID、时间范围、视角或视角集合、采样档位。

输出：实际采样帧号、有序图片、各图视角及时间戳、采样规则版本、是否完整返回所请求的范围。

- 离散：用于较长时间范围的动作发现。
- 中等：用于确认动作顺序和收窄边界范围。
- 逐帧：用于局部过渡及边界不确定性判断。

各档位的步长、窗口上限和每次图片数尚未确定。超长逐帧请求应明确分批或返回约束信息，不能静默降采样。

### observe_object_attributes

输入：已有观察中的目标引用、相关帧和视角。

输出：可见物体属性、依据帧和不可判定项。目标引用应可追溯到实际画面，避免只根据名称补全属性。

## 4. 需要继续讨论的边界

1. 时间范围由谁选择：若要让 Agent 决定“看哪一部分”，需要允许选择合法时间范围或已有窗口。仅选择视角和采样档位不足以表达这一决策。此项是待确认的接口扩展。
2. 单次是否允许选择多视角、是否支持确定性的目标局部裁剪，以及属性工具是否单独调用 VL，均未定稿。
3. 同一个 VL 同时判断动作和调度观察，还是拆成观察调度器与标注模型，尚未定稿。前者可作为将来较简单的研究起点。
4. 属性观察是否必须执行、最终何时允许提交、未解决问题如何表达，需要独立约定。

## 5. 建议由程序固定负责的控制

以下是设计建议，不是已经实现或用户最终确认的要求。

- 初始全程多视角粗覆盖，或提交前覆盖检查，避免只追踪显眼动作。粗覆盖不等于短动作必然被发现。
- 记录已观察的时间、视角和采样密度，避免把稀疏观察误记为逐帧核实。
- 设置调用次数、图片数和运行时间预算；到达预算时保留未解决项，不强迫生成确定边界。
- 记录每次观察的目的、参数、实际图片、返回值以及对动作假设的影响。
- 最终校验连续闭区间、帧号合法性、引用证据可追溯性；结构合法不能替代语义正确性。

## 6. 未来如何判断是否值得引入

与固定流程比较遗漏和多拆、动作语义、边界偏差及不确定性、调用成本、重复运行稳定性。保持模型规模和可访问证据公平，不把更多调用本身当作架构改进。

当前只有两条开发轨迹，不能据此声称泛化成立。现有 v2 标注是用户选定的工作参考，部分边界沿用了模型候选；与其接近不代表获得独立验证的精确接触时刻。
