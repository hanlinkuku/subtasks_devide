# 子任务标注需求说明

## 1. 项目目标

对开源机器人数据集中的每条轨迹进行子任务标注，将完整轨迹划分为若干连续、可定位的子任务片段，并输出对应的动作描述、原子技能、执行机械臂、帧区间、时间区间、任务关联、目标物体属性及执行状态等信息。
最终标注结果统一以 JSON 形式交付，字段结构及示例以下文展示的 JSON 为准。下方 JSON 是最终标注结果示例，不得修改其结构、字段名称、字段类型或层级关系。

## 2. 标注对象与输入信息

每条轨迹应提供可观看的视频，或能够还原为视频的连续图像序列。数据集中如包含轨迹任务名称、任务描述或其他任务级文本，也可以将其作为辅助信息参与标注。
建议根据轨迹是否包含有效的任务名称，灵活选择标注依据：

1. **存在轨迹任务名称**：建议结合轨迹任务名称和视频画面进行子任务标注。任务名称能够提供整条轨迹的目标和语义背景，视频画面则能够反映实际执行过程、动作边界、物体状态变化及完成情况。综合使用两类信息，通常有助于减少仅凭画面产生的理解歧义，提高子任务名称和分段结果的准确性。
2. **不存在轨迹任务名称**：可以直接依据视频画面进行标注，由标注模型或标注人员识别轨迹目标，并生成相应的任务及子任务描述。此时可重点参考动作过程、操作对象、状态变化和最终结果。
3. **任务名称与视频内容存在差异**：建议优先核对视频中的实际执行情况，并将任务名称作为参考信息，必要时记录二者之间的差异，避免任务名称对画面理解造成误导。

以上内容仅作为建议的标注思路，并非对具体标注方法的强制要求。实施方可以根据不同数据集的信息完整度和实际标注效果，选择合适的信息组合方式及技术实现方案；但最终交付的标注结果必须满足本需求规定的结构要求，具体结果架构见后文“最终标注结果示例”。
## 3. 子任务标注要求

- 子任务应对应视频中可观察、相对完整且具有明确目的的动作阶段。
- 每个子任务必须给出准确的起止帧和起止时间，且帧编号与视频实际帧序列一致。
- 子任务描述应准确概括实际动作，不添加视频中无法确认的行为或结果。
- 建议为每个子任务标注一个标准化的原子技能 `skill_id`，例如 `reach`、`grasp`、`move`、`rotate`、`press`、`pull`、`push`、`release` 或 `wait`。技能名称建议统一使用小写英文和下划线，避免同一技能出现多种写法。
- 建议通过 `arm_used` 标注执行该原子技能的机械臂，推荐取值为 `left`、`right`、`both`、`none` 或 `unknown`。`none` 可用于不涉及机械臂的等待或底盘动作，确实无法从画面判断时使用 `unknown`。
- 原则上一个子任务对应一个主要原子技能。如果一个视频片段包含多个具有独立语义且边界可辨识的连续技能，建议进一步拆分为多个子任务；确实无法拆分时，可标注其中起主导作用的技能，并在 `notes` 中补充说明。
- 相邻子任务的边界应清晰，避免无依据的重叠、遗漏或过度切分。
- 涉及操作物体时，应根据可见信息标注目标物体的名称、颜色、形状、材质、尺寸、状态及其他显著属性。无法从视频可靠判断的属性不应臆测。
- 整条轨迹的标注范围应覆盖实际有效内容；静止、等待、无操作等片段如具有任务意义，可作为相应子任务记录。

## 4. 开源数据集格式适配

不同开源数据集的目录结构、视频存储方式、轨迹索引、帧率、任务名称字段和元数据格式可能不同，因此不要求所有原始数据集天然采用同一种格式。

实施方可以选择以下任一方式：

- 针对不同数据集格式分别开发读取与标注适配逻辑；
- 在标注前将不同数据集转换为统一的中间格式，例如 LeRobot 格式，再执行标注。

无论采用哪种方式，都必须满足以下要求：

- 不丢失轨迹与视频、任务名称及原始 episode 标识之间的对应关系；
- 不改变视频帧顺序、帧率语义或轨迹边界；
- 能够准确获得每条轨迹的视频、总帧数、帧率和任务名称（如有）；
- 转换前后应能够追溯到原始数据集、原始轨迹编号和原始文件；
- 源数据没有任务名称时，不得为了格式统一而伪造原始任务名称；
- 最终标注结果必须统一使用下方规定的 JSON 结构，与内部采用何种适配方案无关。

## 5. 交付与验收要求

- 每条轨迹对应一份完整的标注结果json文件，并保留稳定、唯一且可追溯的 `trajectory_id`。
- `trajectory_start`、`trajectory_end`、任务段和子任务帧区间必须与原视频一致。
- 每个子任务应包含 `skill_id` 和 `arm_used`，且同类技能与机械臂取值应在整个交付数据集中保持一致。
- 有轨迹任务名称的数据，建议在标注时参考任务名称并结合视频核验实际过程，以提升标注准确性。
- 无轨迹任务名称的数据，可以直接根据视频内容生成相应的任务及子任务标注。
- 输出文件应使用 UTF-8 编码，确保中英文、符号和标点不出现乱码。
- 最终 JSON 的结构、字段名称、字段类型和层级不得擅自增删或调整。

## 6. 最终标注结果示例

以下 JSON 结构体为最终标注结果示例，其中每个子任务通过 `skill_id` 标识原子技能，通过 `arm_used` 标识执行该技能的机械臂：

{

  // ========== 顶层元数据 ==========
  "trajectory_id": "episode_000000", // 轨迹唯一编号，用于标识该条数据
  "trajectory_start": 0, // 整个轨迹的起始帧编号（通常从0开始）
  "trajectory_end": 596, // 整个轨迹的结束帧编号（总帧数-1）
  "task_name": "用左臂接近温控器" //描述当前轨迹的任务总体名称

  // ========== 子任务列表 ==========
  // 将顶层任务进一步细化为更小的原子动作单元
  "subtasks": [
    {
      // ---------- 核心标识字段 ----------
      "id": 1, // 子任务序号，从1开始递增，全局唯一
      "standard_action_text": "用左臂接近温控器。", // 子任务简短名称，概括核心动作
      "skill_id": "reach", // 标准化原子技能标识，使用统一的小写英文名称
      "arm_used": "left", // 执行该原子技能的机械臂：left/right/both/none/unknown
      "notes": "黑色夹爪从画面左侧进入，向温控器移动并靠近，最终停在温控器右侧附近", // 详细的动作描述和观察记录，包括夹爪位置、物体状态变化等

      // ---------- 时间/帧定位字段 ----------
      "start_frame": 38, // 子任务在视频中的起始帧编号
      "end_frame": 70, // 子任务在视频中的结束帧编号
      "start_time": 2.533, // 起始时间（秒），与帧对应，便于快速定位
      "end_time": 4.667, // 结束时间（秒）

      // ---------- 目标物体属性 ----------
      // 描述当前子任务操作的主要物体的视觉和物理属性，用于物体识别和模型训练
      "target_object_attribute": {
        "name": "TOSHIBA温控器", // 目标物体名称
        "colors": ["白色", "银色"], // 颜色列表
        "shapes": ["矩形"], // 形状列表
        "materials": ["塑料", "玻璃"], // 材质列表
        "sizes": ["手掌大小"], // 尺寸描述
        "others": ["屏幕显示18.0°C", "带触控按钮"], // 其他属性（如状态、位置、特殊标记等）
        "description": "安装在白墙上的白色方形电子温控面板，品牌为TOSHIBA，带液晶屏和物理按键" // 详细描述该物体在场景中的完整特征
      }
    }
    // 可继续添加更多子任务，id依次递增
  ]
}
